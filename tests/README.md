# tests

`tests/` — единственное специальное место Product Unit для исполняемых модулей технической и регрессионной проверки. Тестовый модуль является механическим доказательством соответствующего контракта, а не рабочим инструментом, пользовательским CLI или самостоятельным владельцем нормативного смысла.

Нормативный контракт проверки принадлежит соответствующему Markdown-владельцу в `SYSTEM.md`, `sops/`, `docs/` или README слоя. Исполняемые рабочие возможности Product Unit находятся в `tools/`. Вне `tools/` поставляемый Python допускается как `tests/test_*.py`; другая исполняемая поверхность требует отдельного решения владельца.

В стартовой обвязке `test_harness.py` механически проверяет живые Harness-контракты. Тесты продукта создаются после решения владельца или active PLAN фазы `implementation` / `verification`.

Канонический запуск из корня Product Unit:

```bash
python3 -m unittest discover -s tests -p 'test_*.py'
```

При изменении Harness/tool/test выполняется полный релевантный suite. В остальных проходах выполняются targeted проверки затронутого контракта и применимые safety/integrity checks по `sops/verify-work.md`.

Временные проверки создаются через `mktemp -d` вне поставочного дерева. Каталог `fixtures/` в поставочном дереве не создаётся.

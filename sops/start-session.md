# Старт сессии

Процедура применяется в развёрнутом Workspace; она не создаёт текущее состояние внутри поставки BytePress.

## Порядок

1. Проверить, что текущий рабочий каталог находится внутри точного `WS_<Slug>/`.
2. Прочитать `AGENTS.md` и `SYSTEM.md` применимого контура Harness.
3. Обнаружить ровно один корневой `<Slug>.profile`. Отсутствие профиля или прежний машинный источник в `AGENTS.md` требует остановки и отдельно разрешённого Workspace Update.
4. Из Project Profile получить `Slug`, `sot_mode`, фиксированный корень продукта `<Slug>/`, объявленные части и проверки средствами продукта без исполнения команд. Workspace и продукт проверять отдельными вызовами инструментов.
5. Прочитать принадлежащие Workspace `plans/active/`, `plans/backlog.md`, `plans/roadmap.md`, `logs/` и применимые SOP.
6. Подтвердить ровно один активный WPLAN либо явно записанную неисполняемую контрольную отметку.
7. Определить фазу, точку контроля, разрешённые и защищённые поверхности и ближайшее решение владельца.
8. Выполнять тесты и инструменты продукта только в разрешённом контуре; защищённый исходный продукт проверять на свежей внешней копии.

При `sot_files` Git не читается и Git CLI не вызывается. `sot_git` и `sot_github` обрабатываются по [sot.md](sot.md). Проверки средствами продукта исполняются только явным режимом `check_product.py` с положительным временем ожидания; обнаружение профиля и проверка только состава их не запускают.

## Восстановление состояния Workspace

Порядок восстановления: Project Profile, `AGENTS.md`/`SYSTEM.md` Workspace, активный WPLAN, список задач, дорожная карта, завершённые WPLAN, журналы, затем документы — владельцы смысла. Корень продукта не заменяет планирование Workspace и не получает копию маршрута.

Стартовое состояние агента показывает цель, WROAD/WBACK/WPLAN, фазу, точку контроля, `sot_mode`, запреты, исходные свидетельства и следующий разрешённый шаг.

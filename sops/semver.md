# Версии BytePress и имена поставок

## Область действия

Эта SOP — единственный процедурный владелец версий BytePress Harness и связанных имён. Workspace и поставляемая копия содержат один логический договор; изменение проводится согласованно по карте соответствия, без независимых политик. После Project Start поставленная SOP применяется к Harness данного Workspace, а не задаёт версию пользовательского продукта.

Основа — [SemVer 2.0.0](https://semver.org/lang/ru/): числовая база отражает изменение публичного договора. При стабильном API несовместимость повышает мажорный компонент, совместимое расширение — минорный, совместимое исправление — патч; младшие компоненты при увеличении старшего обнуляются. Начальная серия `0.Y.Z` не заявляет стабильный API. Выбор новой базы определяется характером изменения и разрешённым маршрутом, а не номером WPLAN или фазы.

Ниже заданы дополнительные ограничения BytePress. Общий SemVer допускает более широкий набор предварительных идентификаторов и метаданные сборки; запрет этих форм здесь не является универсальным требованием SemVer.

## Допустимые версии

`VERSION` исходной поставки — единственный источник значения версии BytePress. Допустимы только:

- `X.Y.Z` — окончательный идентификатор;
- `X.Y.Z-dev.N` — предварительная фиксация разработки;
- `X.Y.Z-rc.N` — кандидат всей версии.

`X`, `Y` и `Z` — неотрицательные целые числа без ведущих нулей. `N` — положительное целое без ведущих нулей. Например, `0.5.4-dev.2` и `0.5.4-rc.1` допустимы; `dev-2`, `rc-2`, `dev.0`, `dev.01`, `alpha.1` и добавление `+build` — нет.

Единственная реализация грамматики — `validate_harness_version` в [project_profile.py](../tools/project_profile.py). Чтение VERSION, разбор Profile и Project Start используют её; проверяющий инструмент не вводит собственную грамматику. Байтовый формат VERSION принадлежит [форматам данных](../docs/technical/data-formats.md).

## Фиксация версии программы

Версия меняется при каждом новом зафиксированном изменении разрабатываемых материалов:

- кода;
- правил;
- инструментов;
- навыков;
- тестов;
- действующей документации.

Согласованные правки нескольких файлов могут составлять одну фиксацию. Изменение VERSION входит в эту фиксацию и не вызывает следующего увеличения. Промежуточное редактирование и одноразовая испытательная копия не являются отдельными сохранёнными вариантами.

До фиксации проверить занятые номера по существующим сохранённым состояниям и их свидетельствам. В открытой серии разработки применяется следующий свободный `dev.N` той же разрешённой базы; уже использованный номер не переиспользуется. Новую базу и перевод подготовленного результата в `rc.N` либо окончательную версию применяют только в соответствующем разрешённом маршруте. Упаковка сама такого решения не создаёт; прохождение обеих предварительных стадий не обязательно.

Зафиксированный вариант неизменяем. Его полная версия связывается с существующей ссылкой на сохранённое состояние и свидетельством точного содержимого: например, с архивом и SHA-256 в результате работы. Для BytePress достаточно итога текущего WPLAN и внешнего отчёта о финальном снимке; отдельного реестра или обязательного поля каждого WPLAN нет. Последующее изменение программы получает новый номер, а старое состояние сохраняется.

Самостоятельно не повышают версию:

- чтение и запуск тестов;
- регистрация Feedback и запись результата;
- оперативные записи и трассы;
- удаление собственных одноразовых временных данных;
- упаковка неизменённого содержимого.

Если очистка удаляет исходный файл либо меняется алгоритм очистки или упаковки, это изменение программы и основание новой фиксации. Завершение фазы, WPLAN или сессии само по себе не повышает версию.

## Развёрнутая версия

`harness_version` принадлежит Project Profile и отражает реально развёрнутый Harness. Project Start переносит полный идентификатор из VERSION проверенной поставки. При [Workspace Update](change-management.md#workspace-update) полное значение переносится только после развёртывания и успешного контрольного чтения, в установленном там порядке. Суффикс не отбрасывается; изменение VERSION исходника само не меняет уже развёрнутый Profile.

Версия пользовательского продукта не назначается по версии Harness. Независимыми остаются:

- версия внешнего исполнителя, например Codex;
- `schema_version`;
- `WORK_CONTRACT`;
- версии самостоятельных навыков.

Эти значения и вычисляемые хэши не являются копиями VERSION. Технический PASS, фиксация версии, приёмка и публикация — отдельные факты; ни один из них не подменяет требуемое решение владельца.

## Имена снимков и поставок

Обозначения:

- `B` — числовая база `X.Y.Z`;
- `V` — полный идентификатор из VERSION;
- `I` — независимый номер снимка Workspace.

| Назначение | Форма |
|---|---|
| Полный снимок Workspace BytePress | `YYYY.MM.DD_WS_BytePress_<B>_<I>.tar.gz` |
| Предварительная Product-поставка BytePress | `YYYY.MM.DD_BytePress_<V>.tar.gz` |
| Окончательная Product-поставка BytePress | `bytepress-<B>.tar.gz` |
| Публичная контрольная сумма | `bytepress-<B>.tar.gz.sha256` |
| Выпускная ветка BytePress | `release/<B>` |
| Окончательный тег BytePress | `<B>` |
| Название выпуска | `BytePress <B>` |

Дата фактическая. Для предварительной поставки V уже включает `dev.N` или `rc.N`: суффикс второй раз не добавляется. При окончательной поставке `V = B`. Номер I не связан арифметически с N и проверяется независимо; существующий архив не перезаписывается.

Обычный сопутствующий файл суммы снимка не создаётся; SHA-256 сообщается как `SNAPSHOT_SHA256`. Публичная сумма относится только к окончательной Product-поставке. Новых видов артефактов, предварительных тегов или публикаций этот договор не вводит. Для других Workspace используется их идентичность и собственное соглашение имён; номер BytePress не навязывается пользовательскому продукту.

Порядок полного снимка задаёт [чистое завершение](clean-exit.md), а разрешение Product-поставки, ветки, тега и выпуска — [управление выпуском](release-management.md). Имя не открывает маршрут и не подтверждает приёмку.

## Исторические исключения

Старые поставки, имена, версии и хэши не переписываются. В частности, `2026.09.23_BytePress_0.5.4_candidate-1.tar.gz` сохраняет VERSION `0.5.4` и исходную идентичность; это историческое исключение, а не новая допустимая форма предварительного имени.

При одинаковом номере сравниваются точное содержимое, типы, байты и права по действующему [договору Update](change-management.md#workspace-update), с манифестами и хэшами исходных поставок. Равенство номера не заменяет идентичность и не разрешает пропустить различия или проверку сохранности. Документированная история в действующих материалах сохраняется как история.

# BytePress Harness

## Введение

BytePress Harness — переносимая инженерная обвязка для агентной разработки цифровых продуктов. Она помогает вести работу от первой задачи до проверенной поставки. Человек управляет, агенты исполняют.

Работа ведётся в Workspace — рабочей области проекта. Продукт находится в отдельном каталоге и поставляется без внутренних планов и журналов. Harness содержит документы, процедуры, формы и инструменты этой работы.

Текущая версия — в [VERSION](VERSION); предварительный кандидат предназначен для проверки. BytePress распространяется по [MIT License](LICENSE). [Карта документации](docs/README.md) ведёт к требованиям и техническим подробностям.

## Первый старт

### Подготовка

Нужны:

- Python 3.12+;
- штатный `tar`;
- агент с доступом к файлам и командам.

Распакуйте проверенную поставку в отдельный каталог и откройте этот `BytePress/README.md`. Уже установленные компоненты повторно устанавливать не требуется.

На POSIX проверьте:

```bash
python3 --version
tar --version
```

На Windows в PowerShell:

```powershell
python --version
tar --version
```

Если Python отсутствует, установите Python 3.12+ и переоткройте терминал и приложение агента. Команды и особенности Windows описаны в [нативной инструкции](docs/user/windows.md).

### Создание Workspace

Откройте в агенте каталог `BytePress/` из распакованной поставки. Замените заполнители и оставьте один вариант продукта:

```text
Создай из этой поставки BytePress готовую рабочую область по вводным:
- Название: <название проекта>.
- Техническое имя: <Slug>.
- Цель: <общая цель проекта>.
- Родительский каталог: <точный путь существующего каталога>.
- Продукт: <новый продукт / существующие материалы по точному пути>.

Ожидаемый результат — готовая рабочая область WS_<Slug>. Существующие материалы сохрани; реализацию продукта не начинай.
```

Техническое имя начинается с латинской буквы; далее допустимы латинские буквы, цифры, `_` и `-`. Проверьте показанный агентом будущий состав и подтвердите создание. Затем откройте созданный `WS_<Slug>` новым чатом.

Для существующего продукта укажите его корень. Если у вас только старый снимок Workspace или справочные материалы, используйте [правило выбора операции](docs/user/README.md#как-выбрать). Подробности:

- [новый продукт](docs/user/first-start.md);
- [существующий продукт](docs/user/existing-product.md);
- [после Project Start](docs/user/after-project-start.md).

## Отдельные навыки

BytePress содержит 0 Agent Skills. После создания Workspace можно отдельно установить рекомендуемые навыки SkillPack:

- `simple-first` — минимально достаточное техническое решение;
- `decision-interview` — необходимые решения и уточнения;
- `translate-to-technical-russian` — перевод выбранного текста на технический русский.

В созданном Workspace передайте агенту:

```text
Установи в этот Workspace рекомендуемый SkillPack 0.0.2 по данным skills/README.md. Ожидаю три навыка, доступных Codex после открытия Workspace новым чатом. Реализацию продукта не начинай.
```

[Источник и точные данные установки](skills/README.md#отдельная-установка-рекомендуемого-skillpack) поставляются вместе с Harness и копируются в `skills/README.md` созданного Workspace. После установки откройте Workspace новым чатом.

## Работа и проверка

Передавайте ближайшую задачу с целью, границами и ожидаемым результатом. Например:

- Новый продукт: «Создай первый рабочий вариант <продукт> для <сценарий>. Разрешаю реализацию в этих границах».
- Доработка: «Исправь <проблема> в <путь>. Сохрани остальные возможности и данные; ожидаю <результат>».
- Исследование: «Исследуй <вопрос>, подготовь требования и варианты. Реализацию пока не разрешаю».
- Продолжение: «Продолжи ближайшую разрешённую задачу».

Повторный Project Start для продолжения работы не нужен. Продуктовую приёмку владелец выполняет отдельно.

Проверить структуру созданного Workspace можно из его корня. На POSIX:

```bash
python3 -B tools/check_workspace.py --workspace .
python3 -B tools/check_product.py --workspace .
```

На Windows:

```powershell
python -X utf8 -B tools/check_workspace.py --workspace .
python -X utf8 -B tools/check_product.py --workspace .
```

Ожидаются `WORKSPACE_CHECK: PASS` и `PRODUCT_CHECK: PASS`. Результат самой задачи проверяется дополнительно. [Каталог известных проблем](sops/known-problems.md) помогает распознать повторяющуюся причину и выбрать реакцию в разрешённой границе.

## Обновление

Завершите текущие записи и подготовьте проверенный полный снимок существующего Workspace. Откройте агент из `BytePress/` новой проверенной распакованной поставки. Цель обновления — корень `WS_<Slug>`, содержащий Project Profile и каталог продукта:

```text
Обнови Harness существующей рабочей области из этой поставки BytePress.
- Корень существующего Workspace: <точный путь к WS_<Slug>>.
- Исходный проверенный снимок: <путь и SHA-256>.
- Частные изменения: <что нужно сохранить / отсутствуют>.

Ожидаю рабочую область с обновлённым Harness и сохранёнными продуктом и частными материалами. SkillPack отдельно не обновляй.
```

Проверьте предложенные изменения и отдельно подтвердите их применение. Подготовка снимка и порядок обновления описаны в [Workspace Update](docs/user/workspace-update.md).

```text
Зарегистрируй мой исходный отзыв как Feedback. Ожидаю сохранённую запись и путь к ней; исправления по этой регистрации не начинай.

<исходный текст обратной связи>
```

Если известны версия и обстоятельства, добавьте их в отзыв по [памятке Feedback](docs/user/feedback.md). Передайте запись и необходимые материалы доступным каналом.

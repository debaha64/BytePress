# AGENTS.md — поставка BytePress Harness

## Назначение

Короткая карта агента для поставляемой BytePress Harness `0.5.2`. Этот каталог является статической Product Unit BytePress и не изображает уже инициализированный Workspace.

```text
Человек управляет, агенты исполняют.
Workspace <Slug> делает продукт <Slug>; продукт не управляет Workspace.
```

Статическая поставка не объявляет режим Workspace. Единственный машинный источник состава и SoT развёрнутого Workspace — корневой `<Slug>.profile`. Project Start создаёт новый Workspace; Workspace Update обновляет существующий с сохранением Project, Product и истории.

## Старт агента

1. Прочитать `AGENTS.md` и `SYSTEM.md`.
2. Если Harness уже развёрнут, прочитать единственный `WS_<Slug>/<Slug>.profile`, принадлежащие Workspace `plans/` и `logs/` и применимые SOP.
3. Если выполняется работа над самой поставкой BytePress, использовать внешний маршрут Workspace; в поставке нет локального маршрута Product Unit.
4. Определить фазу, точку контроля, разрешённые поверхности и ближайшее решение владельца.
5. Не исполнять `product_native_checks` при обнаружении, разборе или проверке Project Profile.

В `sot_files` Git CLI не вызывается. Подробные процедуры находятся в [sops/](sops/README.md).

## Статическая поставочная форма

| Слой | Роль |
|---|---|
| `README.md` | вход пользователя и навигация |
| `SYSTEM.md` | системные границы Harness |
| `docs/` | поставляемый смысл, принадлежащий продукту |
| `sops/` | поставляемые процедуры жизненного цикла Workspace |
| `roles/` | ответственность существующих ролей SDLC |
| `skills/` | переносимые Agent Skills |
| `templates/` | статические заготовки и формы будущего Workspace |
| `tools/` | исполняемые возможности Harness: проверки, очистка, разбор Project Profile и Project Start |
| `tests/` | принадлежащие продукту тесты Harness |

`plans/`, `logs/`, корневой `research/` и универсальный `src/` не входят в поставку. После создания они принадлежат Workspace либо конкретному продукту по явно заданному смыслу; наличие `docs/`, `tests/`, `assets/`, `examples/`, файлов сборки или CI не объявляет Product Part автоматически.

## Обязательные границы

1. Корень Workspace имеет имя `WS_<Slug>` и после Project Start содержит непосредственно в нём один корень продукта `<Slug>/` и ровно один `<Slug>.profile`.
2. Product Unit после поставки не читает Project Profile для собственной работы.
3. Product Parts существуют только по декларации `product_parts` и являются каталогами непосредственно в корне продукта.
4. Проверки средствами продукта декларативны; `check_product.py` исполняет их только по явной опции с положительным временем ожидания. Обнаружение, разбор профиля и проверка состава их не запускают.
5. Product Unit не хранит текущий маршрут Workspace и не управляет Workspace.
6. Реализация, Product Acceptance, `release/tag` и изменяющие действия GitHub требуют отдельных решений владельца.
7. `AGENTS.md`, `SYSTEM.md`, `sops/`, `roles/`, `skills/`, `templates/` и `tools/` защищены; точные исключения задаёт активный Workspace WPLAN.
8. Project Start имеет только операции `preview` и `apply`; изменения начинаются только при точной контрольной сумме разрешения.

## Дефект Harness

При дефекте Harness изменения прекращаются с сообщением:

```text
HARNESS_BLOCKER: <краткое описание>
```

Технический PASS не равен Product Acceptance.

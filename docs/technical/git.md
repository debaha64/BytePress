# Git

Этот документ задаёт техническую справку о локальном Git-слое и его проверке. Порядок подготовки и переходов принадлежит [процедуре SoT](../../sops/sot.md), а настройки для пользователя — [инструкции GitHub](../user/github-repository-preparation.md).

## Режимы

1. `sot_files` использует только файловый контроль: Git не читается и Git CLI не вызывается.
2. `sot_git` добавляет локальный репозиторий, `HEAD`, рабочее дерево и локальные изменения.
3. `sot_github` связывает подготовленную локальную копию с ожидаемым репозиторием GitHub через единственный `origin`, отслеживаемую ветвь и локальную ссылку `origin/HEAD`.

Режим сам по себе не разрешает удалённый репозиторий, отправку изменений, PR, слияние, тег, выпуск или изменяющие действия GitHub. Начальная настройка отсутствующего неизменённого репозитория при уже объявленном `sot_git` имеет отдельную процедуру в [sot.md](../../sops/sot.md).

## Идентичность репозитория и URL

Для `sot_github` поле `SOT_GITHUB_REPOSITORY` в `AGENTS.md` содержит `owner/repository`:

- две непустые части, разделённые одним `/`;
- имя репозитория не заканчивается суффиксом `.git`;
- пробельные символы, `:`, `@`, `\`, `?`, `#`, схема URL, имя сервера и данные доступа запрещены;
- сравнение с идентичностью, извлечённой из URL `origin`, выполняется без учёта регистра.

`owner/example.github.io` и `owner/tool.git.adapter` допустимы, а `owner/widget.git` запрещён. Полные правила именования GitHub эта проверка не реализует.

Имя удалённого репозитория фиксировано: `origin`. Поддерживаются HTTPS с `github.com`, стандартная SSH-форма scp, SSH-псевдоним в форме scp и `ssh://git@<host>/owner/repository.git`. Локальный путь, `file://` и данные доступа в HTTP URL запрещены. Для SSH-псевдонима локальная проверка подтверждает только синтаксис и путь репозитория. Настройки `~/.ssh/config`, действительный сервер, аутентификация и права проверяются внешней предварительной проверкой.

Project Profile не хранит URL, ветвь по умолчанию, выпускную ветвь, учётную запись или токен. Идентичность репозитория — отдельная конфигурация Workspace, которая не меняет схему v1.

## Текущая проверка `sot_git`

`check_workspace.py` проверяет:

1. точный корень Workspace;
2. действительный репозиторий и `HEAD`;
3. рабочую ветвь и чистое рабочее дерево;
4. отсутствие удалённого репозитория.

Грязное дерево всегда даёт `FAIL`. История коммитов, reflog и последовательность команд терминала не реконструируются.

## Локальная проверка `sot_github`

После внешней подготовки `check_workspace.py` дополнительно проверяет:

1. ровно один `origin` и поддерживаемые URL получения и отправки изменений;
2. совпадение извлечённого `owner/repository` с `SOT_GITHUB_REPOSITORY`;
3. отслеживаемую ветвь текущей ветви под `origin` и наличие соответствующей локальной удалённой ссылки;
4. символическую ссылку `refs/remotes/origin/HEAD` на существующую `refs/remotes/origin/<branch>`;
5. отсутствие отставания или расхождения историй; равенство и только локальное опережение допустимы.

Неполный путь репозитория, второй удалённый репозиторий, иное имя вместо `origin` или несовпадение идентичности дают `FAIL` без исправления.

Инструмент один раз разбирает режим Project Profile и выбирает ровно один обработчик. Общие проверки Git не вызывают. Инструмент не использует сеть, `fetch`, `pull`, `push`, `gh`, GitHub API, Settings или операции PR и не исправляет состояние. Свежесть внешних метаданных не подтверждается локальным PASS.

В настоящем GitHub Workspace подключение `origin` квалифицирует внешняя предварительная проверка. В автономных тестах без сети разрешён локальный bare-репозиторий `origin` с теми же правилами идентичности, отслеживания ветви и ссылки на ветвь по умолчанию. Такая тестовая среда не доказывает актуальность GitHub.

## Ветви, участники и опубликованная история

Имена ветвей по умолчанию и выпуска, способы слияния, ветви выпуска и срочного исправления задаёт политика репозитория. Это не дополнительные поля режима. Обязательное локальное отражение ветви по умолчанию — `refs/remotes/origin/HEAD`.

Для заполненного репозитория рабочая ветвь исходит из проверенной удалённой версии. Перенос проверенного содержимого файлов не означает автоматическое присоединение независимой истории. Сохранение опубликованной истории обязательно, если владелец отдельно не разрешил иной разрушительный маршрут.

Различаются автор, утверждающий, исполнитель слияния и публикатор. Одна учётная запись может совмещать роли только при совместимых действующих правилах. Утверждение текущего SHA требуется заново после нового изменения; выполнить слияние может другой участник с необходимыми правами. Решение владельца не заменяет обязательную проверку GitHub или утверждение последнего проверяемого изменения другим участником.

## Наблюдение перед выпуском

[Спецификация выпускных свидетельств](release-evidence.md) требует свежих сведений о ссылках, настройках, правилах и правах, а также проверки возможности разделения ролей. Отсутствующее поле `bypass_actors` означает `UNKNOWN`; ответ `404` для классической защиты сам по себе не означает `ABSENT`. Отдельное наблюдение владельца или администратора относится только к текущей точке контроля. Оно не делает автоматический результат положительным и не разрешает будущие записи.

Нормативный порядок принадлежит [release-management](../../sops/release-management.md). Универсальная локальная проверка по-прежнему работает без сети.

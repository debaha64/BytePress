# Проверки Workspace и продукта

Проверки разделены по предмету, чтобы технический результат одного контура не подменял другой.

| Контур | Что подтверждает | Что остаётся за его границей |
|---|---|---|
| Проверка Workspace | Project Profile, режим источника истины, маршрут, свидетельства и полномочия SDLC, ссылки и якоря, соответствие фактических изменений объявленным | содержимое и поведение Product Unit |
| Проверка продукта | корень продукта, объявленные части и рабочие каталоги | точки контроля Workspace, продуктовая приёмка и знание конкретного стека |
| Проверки средствами продукта | результат явно выбранных команд средствами продукта | автоматическая квалификация всего продукта |
| Квалификационные тесты BytePress | конкретный состав поставки и продуктовые контракты BytePress | универсальные проверки и решения владельца |

## Явный запуск

`check_product.py` по умолчанию проверяет только состав. Опции `--run-native-checks --timeout-seconds <N>` включают явный запуск. Инструмент сначала проверяет весь выбранный набор, затем сортирует машинные ID по исходным байтам UTF-8 либо выбирает один точный ID. Команды запускаются как массив аргументов без оболочки, в ограниченном рабочем каталоге, с проверенным исполняемым файлом, унаследованным окружением, закрытым stdin и перехваченными stdout/stderr.

Непосредственно перед каждым запуском контекст проверяется снова. Изменившийся контекст, отсутствие исполняемого файла, превышение времени ожидания или прерывание дают отказ. Отдельного исполняемого файла или модуля запуска проверок нет.

`check_workspace.py` и `check_product.py` не вызывают друг друга. Проверяющий инструмент Workspace не запускает и не импортирует реализацию продукта. Проверяющий инструмент продукта не знает плановый маршрут, точки контроля, стек, `src`, `.sln`, фиксированное число частей или отпечаток BytePress.

Пример из созданного Workspace:

```bash
python3 -B tools/check_workspace.py --workspace .
python3 -B tools/check_product.py --workspace .
python3 -B tools/check_product.py --workspace . --run-native-checks --timeout-seconds 60
```

Последняя команда требует предварительно объявленных и разрешённых `product_native_checks`; [Project Profile](../architecture/project-profile.md) задаёт их поля. Положительное время ожидания ограничивает исполнение. Объявление команды, проверка состава и фактический запуск — разные действия.

## Граница результата

PASS означает соответствие выбранной проверке. Он не доказывает полноту документации, пригодность продукта или готовность к выпуску. [Стратегия тестирования](testing.md) объясняет виды свидетельств; [verify-work](../../sops/verify-work.md) владеет процедурой. Инструмент очистки удаляет только разрешённые временные остатки и имеет отдельный контракт в [жизненном цикле артефактов](artifact-lifecycle.md).

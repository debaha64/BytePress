# Тестирование BytePress

Тесты проверяют поставляемый Harness как продукт. [Тема о проверках](checks.md) объясняет различия между проверкой Workspace, проверкой продукта, собственными проверками продукта и проверками самой поставки BytePress.

## Что покрывает набор тестов

- Синтаксис Project Profile v1, состав Workspace и статическую поставку.
- Все три режима источника истины: изоляцию Git, идентичность репозитория, отслеживаемую ветвь, `origin/HEAD`, расхождения веток и отсутствие неявных сетевых действий.
- Ограничения `Slug` и `PartSlug`, границы файлов и Product Parts.
- Явный запуск средствами продукта: массив аргументов без оболочки, рабочий каталог, изменение контекста, время ожидания, прерывание, стандартный ввод и вывод.
- Project Start для нового и существующего продукта, Workspace Update и свидетельства готовности к выпуску.
- Документационные ссылки, якоря, пользовательскую навигацию и утверждённые устаревшие названия.

Тестовые проекты создаются во временных каталогах. Чтение Project Profile и проверка состава не исполняют объявленные команды. Точное содержимое поставки BytePress, `VERSION` и отпечатки проверяются отдельно от универсальных инструментов Workspace/Product.

## Проверяемое поведение и происхождение ожиданий

Тест выводится из принятой спецификации, а не из желаемого результата запуска. Связь с `REQ-* / INV-* / SCN-*` объясняет, какое требование, инвариант или сценарий он защищает. Тестовая заготовка не создаёт требования или разрешения владельца.

Для изменений поведения используется TDD: содержательный RED подтверждает, что тест обнаруживает отсутствующее поведение, GREEN — что реализация выполняет контракт. Масштаб проверки зависит от `S0/S1/S2`; свойства, требующие суждения читателя, получают ручную оценку вместо формального теста по наличию слов. Порядок и критерии задаёт [verify-work](../../sops/verify-work.md).

Пользовательский вход оценивается по [критериям чтения документации](../../sops/verify-work.md#documentation-review). Хранение данных и GUI проверяются только при применимости. Технический PASS не создаёт `PA-*`, не разрешает выпуск, тег или действия GitHub.

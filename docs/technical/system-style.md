# Русский технический стиль

Человекочитаемый текст помогает читателю понять предмет и выполнить свою задачу. Начинайте с ответа на его вопрос; объясняйте незнакомый термин в точке первого применения.

## Формулировки

- Используйте одну каноническую форму из [глоссария](../terminology/glossary.md).
- Называйте исполнителя и действие: «Агент повторно проверяет контекст перед запуском команды».
- Разделяйте длинные предложения, если в них несколько независимых обязанностей или условий.
- Обычные слова пишите по-русски: «границы», «свидетельство», «контрольное чтение», «предварительная проверка». Кодовое оформление не делает ненужное английское слово термином.
- Сохраняйте отрицание, степень уверенности, условия и модальность исходного контракта.
- Перечисления из трёх и более элементов оформляйте списком.

## Защищённые фрагменты

Сохраняйте точное написание следующих фрагментов:

- код, команды и параметры CLI;
- пути и имена файлов;
- поля и значения JSON, идентификаторы и машинные маркеры;
- официальные названия технологий, API и элементов интерфейса;
- обозначения стандартов и общепринятые сокращения;
- принятые имена Workspace, Product Unit, Harness, Project Profile, Project Start и Workspace Update.

Рядом с незнакомым именем допустимо короткое русское пояснение. Название категории пишите по-русски: «путь», а пример сохраняйте точно: `docs/user/first-start.md`. Поле `bypass_actors` остаётся неизменным; в объяснении пишите «участники, которым разрешён обход правил». Обычное выражение «утверждение текущего коммита» не требует английского слова; машинное состояние `APPROVED` сохраняется.

Редакторская проверка охватывает весь человекочитаемый корпус поставки: вводные документы, системный реестр, документацию, процедуры, роли, формы, индекс навыков и пользовательские сообщения инструментов. Машинные фрагменты сверяются отдельно. Стиль исправляют по смыслу предложения; глобальная замена слов для этого не подходит.

## Границы

Пользовательская инструкция может содержать необходимые действия и наблюдаемый результат. Порядок проверки полномочий агента, прохождения точек контроля, остановки и восстановления принадлежит SOP. История не переписывается ради стиля; в принятых свидетельствах ссылки обновляют только по отдельному разрешению.

[Паспорт](../product/product-passport.md) хранит текущую языковую поддержку. Изменение терминов регулирует [терминологическая процедура](../../sops/terminology.md), а критерии чтения задаёт [процедура проверки](../../sops/verify-work.md#documentation-review). Механическая проверка не оценивает качество русского синтаксиса.

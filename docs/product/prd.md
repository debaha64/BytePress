# Требования к продукту

BytePress Harness предоставляет средства управляемой работы в Workspace с единственным самостоятельным Product Unit. Этот документ задаёт общий поддерживаемый контракт; точные правила принадлежат указанным спецификациям.

## Возможности и критерии

| Возможность | Поддерживаемый результат и критерии | Точный контракт |
|---|---|---|
| Project Profile | строгий JSON по схеме v1; пути выводятся из имени; неизвестные поля, неоднозначность регистра и выходы за границы отвергаются; сериализация воспроизводима | [Project Profile](../architecture/project-profile.md) |
| Состав продукта | один корень продукта совпадает с границей поставки; необязательные прямые части имеют явную ответственность; остальные внутренние каталоги не запрещаются | [Доменная модель](../architecture/domain-model.md) |
| Project Start | `preview` без записи; `apply` только при совпадении SHA-256; отдельный Workspace, четыре поля профиля, начальный `sot_files` и только WROAD; исходные материалы неизменны | [Project Start](../technical/project-start.md) |
| Новый и существующий продукт | новый корень пуст; существующий копируется с сохранением байтов и POSIX-режимов доступа; исключаются только точно разрешённые пути VCS; код не запускается | [Project Start](../technical/project-start.md) |
| Проверки | Workspace проверяет управление и источник истины; Product проверяет состав и только явно запускает объявленные команды; контуры не вызывают друг друга | [Проверки](../technical/checks.md) |
| Workspace Update | обновление Harness сохраняет идентичность, продукт, историю и источник истины; `harness_version` меняется после контрольной проверки | [Обновление Workspace](../user/workspace-update.md), [процедура](../../sops/change-management.md#workspace-update) |
| Управляемый жизненный цикл | роли, соседние фазы и свидетельства имеют явный контракт; техническая проверка, оценка пригодности, приёмка и разрешение выпуска разделены | [Точки контроля](../technical/phase-gates.md) |
| Выпускные свидетельства | предварительные проверки, проверка точного PR и контрольное чтение сохраняют границы доказательности; скрытые необходимые факты дают `OWNER_ACTION_REQUIRED` | [Свидетельства выпуска](../technical/release-evidence.md) |

## Общие ограничения

- Исполнение использует только стандартную библиотеку Python; внутренний стек продукта выбирается отдельно.
- Поставка не содержит текущих планов, журналов и исследований или синтетических решений проекта; формы не являются исполненными записями.
- Product Unit после поставки не зависит от Project Profile; универсальный `src/` и фиксированное число частей не требуются.
- Проверки работают без автоматического исправления. Чтение профиля и проверка структуры не исполняют команды продукта.
- Project Start не обновляет существующий Workspace, не создаёт состояние Git/GitHub и не открывает первый WBACK/WPLAN.
- Физическая заготовка Product Seed, второй начальный режим развёртывания, отдельный инструмент или платформа миграции и автоматические выпуск, теги и изменяющие действия GitHub не поддерживаются.

## Критерии готовности изменения

Версия поставки согласована с `VERSION`; поставка самодостаточна, состав и POSIX-режимы доступа проверены. Для изменённого поведения есть проверяемая спецификация и свидетельства предварительного написания тестов. Документация и формы соответствуют текущему контракту; ссылки, якоря и пользовательская навигация проходят объективные проверки. Ясность и полнота требуют проверки человеком по [verify-work](../../sops/verify-work.md#documentation-review).

Техническая проверка фиксируется во внешнем Workspace и не выполняет Product Acceptance или Release Authorization. [Стратегия тестирования](../technical/testing.md) объясняет виды свидетельств.

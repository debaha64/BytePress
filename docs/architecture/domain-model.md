# Модель предметной области

Эта модель объясняет состав проекта и границу поставляемого продукта. Точный формат объявления задан в [Project Profile](project-profile.md).

## Сущности и значения

- `Slug` — переносимое имя проекта из имени `<Slug>.profile`. Оно сохраняет регистр; точные ограничения имени принадлежат контракту Project Profile.
- Project Profile — принадлежащее Workspace объявление состава проекта. В нём нет планов, истории, точек контроля, состояния выпуска или приёмки.
- Корень Workspace — `WS_<Slug>/`.
- Product Unit — самостоятельный поставляемый продукт в единственном каталоге `<Slug>/` непосредственно внутри Workspace.
- Product Part — необязательная архитектурная часть, явно объявленная через `PartSlug` и размещённая непосредственно внутри корня продукта.
- `PartSlug` — имя части с теми же ограничениями и правилами совпадения имён, что у `Slug`. Отдельное поле `path` для него не задаётся.
- Граница поставки — каталог `<Slug>/`, совпадающий с корнем продукта.
- Проверка средствами продукта (техническое имя `native check`) — собственная проверка продукта с машинным ID, массивом аргументов и нормализованным относительным рабочим каталогом. Чтение Project Profile не исполняет команду; запуск доступен через явный режим `check_product.py`.
- Проверка Workspace — проверка внешнего состава проекта, планирования, режима источника истины и файлов Workspace без исполнения продукта.
- Проверка продукта — проверка границы поставки, объявленных частей и собственных проверок продукта. Он не зависит от маршрута Workspace или технологического стека продукта.
- Project Start — создание Workspace через предварительный просмотр `preview` и разрешённое владельцем применение `apply`, связанное с контрольной суммой просмотра.
- Product Seed — правило Project Start для нового продукта: создаётся только пустой корень продукта. Это не каталог или готовый пример приложения. Существующий продукт копируется с сохранением исходника.

## Инварианты

1. `Slug` не дублируется полем JSON: имя Workspace, корень продукта и граница поставки выводятся из него.
2. Регистр сохраняется; совпадение имён без учёта регистра приводит к FAIL.
3. В Workspace один корень продукта. Несколько независимых корней не поддерживаются.
4. Product Parts не выводятся из наличия `docs/`, `tests/`, `assets/`, `examples/`, манифестов, сборки или CI.
5. Общие каталоги продукта допустимы без объявления частями: Project Profile не является списком разрешённых файлов.
6. Product Unit после поставки не зависит от Project Profile.
7. Планы, журналы и свидетельства Workspace находятся вне границы поставки продукта.

Спецификация, проектное решение, тест и свидетельство проверки имеют разное назначение. Project Start реализует эту модель, но не определяет внутреннюю архитектуру продукта, следующую задачу, продуктовую приёмку или разрешение выпуска.

## Пример

```text
WS_Notes/
├── Notes.profile   # состав проекта и режим источника истины
├── plans/          # разрешённая работа
├── logs/           # факты и решения
└── Notes/          # самостоятельный продукт и граница поставки
```

Каталог внутри `Notes/` становится Product Part только после явного объявления архитектурной ответственности в [Project Profile](project-profile.md). Наличие каталога само по себе ничего не объявляет.

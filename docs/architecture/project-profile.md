# Project Profile

Project Profile описывает состав Workspace и режим источника истины. Этот документ задаёт поставляемый контракт схемы v1. Профиль принадлежит Workspace; самостоятельная Product Unit после поставки от него не зависит.

## Имя и состав проекта

После Project Start непосредственно в `WS_<Slug>/` находится ровно один `<Slug>.profile`. Имя файла без расширения — единственный источник `Slug`. Из него выводятся `WS_<Slug>` и корень продукта `<Slug>/`, совпадающий с границей поставки. Дублирующие поля `slug`, `workspace_name`, `product_root`, `product_path`, `delivery_boundary` запрещены.

`load_project_profile()` отвергает символическую ссылку в конечном аргументе корня Workspace, затем нормализует абсолютный, относительный или `.` путь. Для Workspace, продукта и объявленных частей проверяются реальные записи родительского каталога: требуется ровно одно совпадение без учёта регистра, при этом написание должно точно совпадать. Отсутствие пути, неверный регистр единственной записи и коллизия регистра — разные ошибки. Остальные пути внутри продукта не ограничиваются этим списком.

## Схема v1

| Поле | Значение |
|---|---|
| `schema_version` | обязательное целое число `1` |
| `harness_version` | обязательная непустая версия успешно развёрнутого Harness |
| `sot_mode` | обязательное `sot_files`, `sot_git` либо `sot_github` |
| `display_name` | обязательная непустая строка для человека; в путях не участвует |
| `product_parts` | необязательный объект `{PartSlug: {responsibility}}` |
| `product_native_checks` | необязательный объект `{machine_id: {command, working_directory}}` |

Необязательное поле может отсутствовать. Если `product_parts` или `product_native_checks` присутствует, его значение — объект JSON; `null` запрещён. Неизвестные поля запрещены на любом уровне схемы.

JSON использует UTF-8 без BOM. Комментарии, завершающая запятая, нечисловые значения вроде `NaN`, бесконечности и повторяющиеся ключи запрещены. Верхний уровень — объект. Значения `harness_version`, `display_name`, `responsibility`, `working_directory` и каждый аргумент команды содержат только скалярные значения Unicode: непарные суррогатные кодовые единицы запрещены, обычный Unicode допустим.

Каноническая сериализация использует UTF-8, отсортированные ключи, отступ `2`, `ensure_ascii=false` и ровно одну завершающую LF. Отсутствующие необязательные поля не заменяются пустыми заглушками. Для каждого принятого профиля сохраняется результат цикла `parse -> canonical serialize -> parse`.

## Части продукта

`PartSlug` задаёт имя непосредственного дочернего каталога корня продукта; отдельного `path` нет. `responsibility` обязательна и непуста. Ошибочный регистр, коллизии регистра, отсутствие объявленного корня, разделитель пути, переход через `..` и символическая ссылка вместо корня части дают FAIL. Внутреннее устройство части выбирает продукт.

## Объявленные проверки

Машинный ID соответствует `^[A-Za-z][A-Za-z0-9_.-]*$`. `command` — непустой массив непустых строк аргументов; строка команды оболочки запрещена. `working_directory` — существующий нормализованный относительный каталог от корня продукта. Абсолютные пути POSIX/Windows, префикс диска Windows, `..` и выход через символическую ссылку запрещены.

В схеме v1 нет полей `shell`, `environment`, `dependencies`, `matrix`, `retry`, `continue_on_error`, встроенных скриптов, ветвей по платформам или конфигурации контейнеров. Порядок ключей JSON не определяет порядок исполнения. [Проверки](../technical/checks.md) описывают явный запуск; чтение профиля команд не выполняет.

## API и граница создания

- `parse_project_profile(data, profile_name)` проверяет JSON и схему без чтения состава файловой системы.
- `load_project_profile(workspace_root)` обнаруживает профиль и проверяет связанные пути, части и рабочие каталоги.
- `serialize_project_profile(profile_name, document)` возвращает воспроизводимые байты.

API находится в `tools/project_profile.py`. Project Start использует каноническую сериализацию; проверка Workspace читает профиль без исполнения команд, а проверка продукта сверяет его в контексте файловой системы. Эти операции не управляют порядком вызова проверяющих инструментов.

Сериализация сама не создаёт Workspace, Product Seed или файл профиля. Поставка не содержит файла-заглушки `*.profile`. [Workspace Update](../../sops/change-management.md#workspace-update) сохраняет проект, продукт, историю и источник истины; `harness_version` меняется только после проверки результата.

[Доменная модель](domain-model.md) объясняет сущности, [Project Start](../technical/project-start.md) — создание среды.

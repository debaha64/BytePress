# Архитектура BytePress

BytePress разделяет управление работой и поставляемый продукт. Это позволяет сохранить внутренний контекст проекта и передать пользователю самостоятельный Product Unit.

| Контекст | Ответственность | Связь |
|---|---|---|
| Управление проектом | цель, задачи и решения владельца | Workspace WROAD/WBACK/WPLAN и журналы |
| Harness | общий порядок и проверяемые границы работы | документы, SOP, роли, формы и инструменты |
| Продукт | поведение и внутренняя архитектура продукта | собственный корень, документация, тесты и выбранный стек |
| Развёртывание / Project Start | создание отдельной рабочей среды | поставка → Workspace через `preview/apply` |
| Проверка / выпуск | проверка и свидетельства передачи | раздельные технические результаты и решения владельца |

[Доменная модель](domain-model.md) задаёт сущности и границы. [Project Profile](project-profile.md) явно задаёт состав проекта; [Project Start](../technical/project-start.md) материализует среду; [проверки](../technical/checks.md) подтверждают каждый свой контракт.

Поставка BytePress содержит средства работы, а конкретные планы, журналы и решения появляются во внешнем Workspace. Внутренняя структура Product Unit не выводится из структуры Harness и не ограничивается универсальной папкой `src/`.

Архитектурные решения и их проверка выполняются по [процедуре архитектурной работы](../../sops/architecture.md); этот документ объясняет устройство продукта.

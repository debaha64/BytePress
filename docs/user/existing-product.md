# Существующий продукт в новом Workspace

Этот путь создаёт новую рабочую среду и копирует в неё существующий продукт. Исходный каталог остаётся неизменным; операция не означает продуктовую приёмку.

## Подготовить

- Укажите каталог самого продукта, например `~/products/Notes`; не передавайте весь старый `WS_Notes`.
- Выберите свободное имя нового Workspace и существующий родительский каталог.
- Проверьте вложенные системы контроля версий. Для каждого исключаемого объекта VCS требуется точный относительный путь.

Из каталога распакованного BytePress выполните:

```bash
python3 -B tools/new_project.py preview --source-distribution . --destination-parent ~/code --slug Notes --display-name "Личные заметки" --wroad "Продолжить развитие заметок" --product existing --existing-product ~/products/Notes
```

Если источник содержит `.git`, повторите `preview` с `--exclude-vcs-path .git`. Для каждого вложенного объекта VCS нужен свой флаг с точным путём. Не исключайте обычные файлы продукта под видом VCS. Допустимые типы и ограничения описаны в [Project Start](../technical/project-start.md#существующий-продукт).

Проверьте источник, место назначения, исключения и состав копирования. Затем выполните ту же команду с `apply` вместо `preview`, сохранив все входы и добавив `--authorization-sha256 PREVIEW_SHA256` с контрольной суммой этого `preview`.

## Проверить результат

В `~/code/WS_Notes/Notes` должна находиться копия продукта без разрешённых исключений VCS, с прежним содержимым и POSIX-режимами доступа. Вложенного `Notes/Notes` быть не должно. Запустите из нового Workspace:

```bash
python3 -B tools/check_workspace.py --workspace .
python3 -B tools/check_product.py --workspace .
```

PASS подтверждает структуру; код и тесты скопированного продукта при создании не исполняются. Их запуск станет отдельной явно разрешённой работой. Продолжите по [следующим шагам](after-project-start.md).

При отказе проверьте точные пути источника и назначения и сообщение `preview`. Символические и жёсткие ссылки, специальные узлы и неподдерживаемые типы объектов VCS не копируются. Восстановление описано в [техническом контракте](../technical/project-start.md#восстановление).

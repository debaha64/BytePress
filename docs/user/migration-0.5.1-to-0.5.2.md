# Переход Workspace 0.5.1 → 0.5.2

Эта тема описывает изменения конкретных версий. Общие условия и ожидаемый результат находятся в [обновлении Workspace](workspace-update.md), процедура — в [change-management](../../sops/change-management.md#workspace-update).

## Что меняется

- Корневой `<Slug>.profile` становится единственным машинным источником состава проекта и `sot_mode`; прежний `SOT_MODE` в `AGENTS.md` удаляется после анализа потребителей.
- `check_workspace.py` проверяет Workspace, а `check_product.py` — состав продукта и явно запущенные проверки средствами продукта.
- Project Start создаёт отдельный Workspace; для существующей среды применяется Workspace Update.
- Корень продукта совпадает с границей поставки; продукт не хранит текущий маршрут Workspace и не зависит от профиля после поставки.

## Что проверить владельцу

План обновления должен сохранять продукт, историю, частные материалы и прежний режим источника истины. Новые копируемые файлы сопоставляются с поставкой, создаваемые и частные тексты — с их владельцами смысла. [Project Profile](../architecture/project-profile.md) описывает новый контракт.

Успешный результат подтверждается проверками состава, происхождения инструментов и сохранности данных; лишь затем обновляется `harness_version`. Переход не выполняет приёмку продукта или выпуск.
